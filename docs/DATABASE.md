# Текущая структура базы данных

Описание соответствует ORM-моделям в [`backend/app/models`](../backend/app/models/)
и начальной миграции Alembic
[`093e886bdc8e`](../backend/alembic/versions/093e886bdc8e_initial_schema.py).
Это схема из исходного кода; состояние запущенного экземпляра PostgreSQL
при подготовке документа не проверялось.

Редактируемая ER-диаграмма: [`db-er-diagram.drawio`](db-er-diagram.drawio).
Ранее экспортированный `db.png` может отличаться от обновлённой схемы.

## Общая организация

База предназначена для пользователей, чатов, участия в чатах, сообщений,
их текста, вложений и отметок прочтения. В прикладной схеме семь таблиц.
Alembic дополнительно использует служебную таблицу `alembic_version`
для хранения текущей ревизии; она не является ORM-сущностью приложения.

Целевая СУБД — PostgreSQL; локальный Compose использует PostgreSQL 17.
В таблицах ниже приведены PostgreSQL-типы. `TIMESTAMPTZ` соответствует
`DateTime(timezone=True)`: PostgreSQL хранит момент времени, а отображает
его в часовом поясе сессии; исходное название часового пояса не сохраняется.

`PK` — первичный ключ, `FK` — внешний ключ. Все столбцы обязательны
(`NOT NULL`), кроме явно отмеченных `deleted_at` и `edited_at`.
Автоматически генерируются только отдельные `id` пользователей, чатов,
сообщений и вложений. Остальные идентификаторы задаются ссылками на
существующие записи. Первичные ключи также обеспечивают уникальность.

## Таблицы

### `users` — пользователи

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `id` | `INTEGER` | PK, автоинкремент | Идентификатор пользователя |
| `username` | `VARCHAR(255)` | NOT NULL | Имя пользователя; уникальность не требуется |
| `login` | `VARCHAR(255)` | NOT NULL | Логин для идентификации пользователя |
| `password_hash` | `VARCHAR(255)` | NOT NULL | Хеш пароля |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `now()` | Время создания |

Индекс `ix_lower_login` — уникальный индекс по выражению `lower(login)`.
Таким образом, логины `Alice` и `alice` конфликтуют. Сам столбец сохраняет
исходный регистр. Нормализация пробелов не предусмотрена. Проверки формата
логина, алгоритма хеширования и содержимого `password_hash` в схеме отсутствуют.

### `chats` — чаты

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `id` | `INTEGER` | PK, автоинкремент | Идентификатор чата |
| `type` | `chat_type_enum` | NOT NULL | Вид чата |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `now()` | Время создания |

Название, описание и отдельный столбец владельца отсутствуют. Роль владельца
задаётся в `chat_members`. Тип чата сам по себе не ограничивает число участников
и не задаёт правила публикации сообщений.

### `chat_members` — участие пользователей в чатах

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `user_id` | `INTEGER` | PK (часть), FK → `users.id`, NOT NULL | Участник |
| `chat_id` | `INTEGER` | PK (часть), FK → `chats.id`, NOT NULL | Чат |
| `joined_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `now()` | Время вступления |
| `role` | `chat_member_role_enum` | NOT NULL | Роль участника |

Составной PK: `(user_id, chat_id)`. Один пользователь может состоять во многих
чатах, но в конкретном чате для него возможна только одна запись участия.
Для `role` нет значения по умолчанию: роль необходимо передать явно.
Схема допускает отсутствие владельца и нескольких владельцев одного чата.

### `messages` — сообщения

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `id` | `INTEGER` | PK, автоинкремент | Идентификатор сообщения |
| `chat_id` | `INTEGER` | FK → `chats.id`, NOT NULL | Чат сообщения |
| `sender_id` | `INTEGER` | FK → `users.id`, NOT NULL | Отправитель |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `now()` | Время создания |
| `deleted_at` | `TIMESTAMPTZ` | NULL разрешён, без DEFAULT | Время логического удаления |

Текст и вложения вынесены в отдельные таблицы. FK отправителя проверяет только
существование пользователя: членство в чате через `chat_members` не проверяется.
`deleted_at` — поле для отметки удаления. Его заполнение не удаляет строку,
не очищает текст и вложения и не добавляет автоматическую фильтрацию запросов.

### `message_content` — текст сообщения

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `message_id` | `INTEGER` | PK, FK → `messages.id`, NOT NULL, без автоинкремента | Сообщение |
| `text` | `TEXT` | NOT NULL | Текст |
| `edited_at` | `TIMESTAMPTZ` | NULL разрешён, без DEFAULT | Время редактирования |

Общий ключ с `messages` обеспечивает не более одной текстовой записи
на сообщение. Наличие текста необязательно: у сообщения может не быть
строки `message_content`. Пустая строка разрешена. Ограничение длины текста
и автоматическое обновление `edited_at` не заданы.

### `message_attachments` — вложения

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `id` | `INTEGER` | PK, автоинкремент | Идентификатор вложения |
| `message_id` | `INTEGER` | FK → `messages.id`, NOT NULL | Сообщение |
| `storage_key` | `VARCHAR(255)` | NOT NULL | Ключ файла во внешнем хранилище |
| `mime_type` | `mime_type_enum` | NOT NULL | Тип содержимого |
| `position` | `INTEGER` | NOT NULL | Позиция вложения в сообщении |
| `size_bytes` | `INTEGER` | NOT NULL | Размер в байтах |

В БД хранится ключ файла и метаданные, а не само содержимое файла.
ORM загружает коллекцию `Message.attachments` с сортировкой по `position`.
Уникальность `(message_id, position)` и `storage_key` не установлена;
при равных позициях дополнительный порядок не определён. CHECK-ограничений
на неотрицательные `position` и `size_bytes` нет. Значений по умолчанию нет.
Удаление ORM-строки вложения само по себе не удаляет файл из внешнего хранилища.

### `message_reads` — отметки прочтения

| Столбец | Тип | Ограничения и значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `user_id` | `INTEGER` | PK (часть), FK → `users.id`, NOT NULL | Прочитавший пользователь |
| `message_id` | `INTEGER` | PK (часть), FK → `messages.id`, NOT NULL | Прочитанное сообщение |
| `read_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `now()` | Время прочтения |

Составной PK `(user_id, message_id)` имеет имя `message_reads_pk`.
На одну пару пользователя и сообщения допускается одна отметка прочтения.
История повторных прочтений не хранится. Членство читателя в чате сообщения
на уровне БД не проверяется. `read_at` не обновляется автоматически.

## Перечисления PostgreSQL

В базе используются нативные ENUM-типы. Хранятся строковые значения Python Enum,
например `private`, а не имя элемента `PRIVATE`.

| Тип | Допустимые значения | Столбец |
| --- | --- | --- |
| `chat_type_enum` | `private`, `group`, `channel` | `chats.type` |
| `chat_member_role_enum` | `owner`, `admin`, `member` | `chat_members.role` |
| `mime_type_enum` | `image/jpeg`, `image/png`, `image/gif`, `image/webp`, `audio/mpeg`, `audio/ogg`, `video/mp4`, `video/webm`, `application/pdf`, `text/plain`, `application/octet-stream` | `message_attachments.mime_type` |

Для ролей и MIME-типов ORM дополнительно включает `validate_strings=True`.
Ни у одного enum-столбца нет значения по умолчанию.

## Связи и кардинальности

| Родитель | Дочерняя таблица / FK | Кардинальность от родителя |
| --- | --- | --- |
| `users` | `chat_members.user_id` | 1 → 0..N |
| `chats` | `chat_members.chat_id` | 1 → 0..N |
| `chats` | `messages.chat_id` | 1 → 0..N |
| `users` | `messages.sender_id` | 1 → 0..N |
| `messages` | `message_content.message_id` | 1 → 0..1 |
| `messages` | `message_attachments.message_id` | 1 → 0..N |
| `users` | `message_reads.user_id` | 1 → 0..N |
| `messages` | `message_reads.message_id` | 1 → 0..N |

Каждая дочерняя строка обязана ссылаться ровно на одного существующего
родителя по каждому FK. Однако родитель не обязан иметь дочерние строки.
`chat_members` реализует связь многие-ко-многим пользователей и чатов,
а `message_reads` — пользователей и прочитанных сообщений.

Схема допускает сообщение без текста и вложений, а также сообщение,
содержащее одновременно текст и несколько вложений. Это не ограничено CHECK,
триггером или другим межтабличным правилом.

## Удаление: БД и ORM

У внешних ключей не указаны `ON DELETE CASCADE` или `ON UPDATE CASCADE`.
В PostgreSQL действует стандартное `NO ACTION`. Прямой SQL DELETE родителя
при наличии ссылающихся строк будет отклонён, если зависимости не удалены
или не изменены в допустимом порядке.

На уровне SQLAlchemy настроено `cascade="all, delete-orphan"`:

| Родитель / коллекция или связь | Что ORM удаляет вместе с родителем |
| --- | --- |
| `Chat.members` | Участия в удаляемом чате |
| `Chat.messages` | Сообщения чата и далее их дочерние записи |
| `User.chat_memberships` | Участия удаляемого пользователя |
| `User.message_reads` | Отметки прочтения пользователя |
| `Message.message_reads` | Отметки прочтения сообщения |
| `Message.message_content` | Текст сообщения |
| `Message.attachments` | Вложения сообщения |

`delete-orphan` также удаляет дочернюю запись, исключённую из соответствующей
ORM-связи, при flush. Для `Message.message_content` дополнительно задан
`single_parent=True`; уникальность текста на сообщение в БД обеспечивает PK.

У `User.messages` каскада удаления нет. Удаление пользователя, отправившего
сообщения, требует отдельного решения для этих сообщений; обязательный
`messages.sender_id` не позволяет просто обнулить ссылку. ORM-каскады
не распространяются на прямой SQL и bulk DELETE.

## Индексы и границы гарантий

Помимо индексов первичных ключей явно задан только `ix_lower_login`.
Дополнительные индексы на FK, время создания и позиции вложений отсутствуют.
PostgreSQL не создаёт индекс на дочернем FK автоматически. Составные PK
начинаются с `user_id`; отдельный индекс по `chat_members.chat_id` или
`message_reads.message_id` не объявлен.

`now()` — серверное значение по умолчанию при INSERT без указанного времени;
оно не обновляет столбцы при UPDATE. В PostgreSQL это время начала транзакции.
Для `deleted_at` и `edited_at` при отсутствии значения получается NULL.
Триггеры для автоматического редактирования, удаления и прочтения не заданы.

На прикладном уровне потребуется определить правила, которых пока нет в схеме:

- число участников приватного чата, наличие и количество владельцев;
- права ролей на отправку сообщений и управление чатом;
- проверку членства отправителя и читателя в чате;
- допустимость пустых сообщений, текста и ключей файлов;
- допустимые размеры и позиции вложений, их уникальность и очистку файлов;
- фильтрацию логически удалённых сообщений и обновление временных отметок.

## Миграции

Начальная ревизия `093e886bdc8e` создаёт семь прикладных таблиц,
три ENUM-типа и индекс `ix_lower_login`. Команды запуска приведены
в [README](../README.md#миграции).

Текущий `downgrade()` удаляет таблицы в обратном порядке зависимостей
и индекс логина, но не содержит явного удаления ENUM-типов. Полноту отката
и повторное применение после отката следует отдельно проверить на PostgreSQL;
этот документ не утверждает, что такой цикл уже проверен.
